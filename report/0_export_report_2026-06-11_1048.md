## 3. 핵심 발견 / 문제점

### 기술·구현 Gap
| 영역 | README 요구 | 현재 상태 |
|------|------------|----------|
| 설계 (OCP/SRP) | 인터페이스·클래스 분리 | 절차형 단일 함수 |
| 입력 검증 | 음수 포함 | 음수 검증 없음 |
| 테스트 | 단위 변환·검증 TC | **0건** |
| 설정 외부화 | JSON/YAML | 하드코딩 |
| 동적 단위 등록 | `1 cubit = 0.4572 meter` | 미구현 |
| 출력 포맷 | JSON / CSV / 표 | `print` 고정 |

### Mom Test에서 드러난 Pain Points
1. **범위 불명확** — README 전체 vs 36줄 프로토타입 gap을 PM에게 확인하지 않음
2. **설계 부재** — 단위 추가 시 `if/elif`, 변환식, `print` 3곳 수동 수정 필요
3. **검증 방식 취약** — 테스트 없이 수동 5~7회 실행으로 "그럴듯함" 판단
4. **확인 미루기 패턴** — "데모 됐으니 OK", `spec` 브랜치를 미루기 명분으로 사용
5. **미검증 항목** — 음수, 반올림(`8.2 feet`), feet↔yard 교차 변환, 부동소수점 오차

### 프로세스 리스크
- git revert/재작성 커밋 없음 → gap 인지 후에도 구조 변경 미착수
- PM 확인 없이 "중간 산출물"이라 자체 정의
- 개발 환경 인프라 부재 (`requirements.txt`, `.gitignore`, CI 없음)
